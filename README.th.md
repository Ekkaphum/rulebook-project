# โปรเจกต์ Rulebook

**เขียนกฎบอร์ดเกมให้คนใช้งานได้จริง**

คู่มือเรื่องการออกแบบ rulebook บอร์ดเกม ที่มีการอ้างอิงแหล่งที่มาทุกข้อความ สังเคราะห์จาก
แหล่งข้อมูลปฐมภูมิ 106 แหล่ง ทั้งฟอรั่มและบล็อกบน BoardGameGeek, style guide ของสำนักพิมพ์,
บรรณาธิการ rulebook อาชีพ และงานเขียนด้านการเข้าถึง

เว็บไซต์: **https://rulebook-project.vercel.app/th** · [English](README.md)

## มีอะไรอยู่ในนี้บ้าง

| ไฟล์ | คืออะไร |
| --- | --- |
| `deliverables/วิธีสร้าง Rulebook ที่ดี.docx` | คู่มือฉบับเต็มภาษาไทย เจ็ดภาค |
| `deliverables/คู่มือเขียน Rulebook ฉบับแชร์ความรู้.docx` | ฉบับเล่าสู่กันฟัง เขียนแบบไม่เป็นทางการ |
| `deliverables/ฐานข้อมูลงานวิจัย Rulebook.xlsx` | ฐานข้อมูลงานวิจัย 10 ชีต ทุกแถวมี URL ที่คลิกได้ |

| `deliverables/Rulebook_Research_Database.xlsx` | ฐานข้อมูลฉบับภาษาอังกฤษ |
| `web/` | เว็บไซต์ Next.js สองภาษา พร้อมระบบค้นหาและเช็กลิสต์แบบติ๊กได้ |

### ฐานข้อมูล (10 ชีต)

- **01_แหล่งข้อมูล** — เอกสาร 106 ชิ้นที่เก็บมา พร้อม URL และช่วงปี
- **02_องค์ความรู้** — 127 ข้อค้นพบใน 14 หมวด แต่ละข้อมีเหตุผล หลักฐาน และการอ้างอิง
- **03_rulebook_ที่ควรศึกษา** — 35 เล่มที่ถูกยกเป็นตัวอย่างดี และสิ่งที่ถูกชมอย่างเจาะจง
- **04_rulebook_ที่ถูกวิจารณ์** — 33 เล่มที่ถูกระบุว่ามีปัญหา และรูปแบบความล้มเหลวที่เฉพาะเจาะจง
- **05_template_โครงสร้าง** — ลำดับหัวข้อ 10 แบบจากแหล่งอ้างอิงต่างกัน วางเทียบกัน
- **06_กฎการเขียน** — 26 กฎที่เป็นรูปธรรม พร้อมตัวอย่างถูก/ผิด
- **07_เช็กลิสต์** — เช็กลิสต์ QA ก่อนพิมพ์ 46 ข้อ ใน 8 ระยะ
- **08_ตัวเลขอ้างอิง** — 16 จุดอ้างอิงเชิงปริมาณ (ขนาดตัวอักษร ความต่างสี ค่าจ้าง เวลา)
- **09_รูปแบบความล้มเหลว** — ระบบจำแนกความล้มเหลว แยกออกมาให้กวาดตาได้เร็ว

## รันเว็บบนเครื่องตัวเอง

```bash
cd web
npm install
npm run dev
```

แล้วเปิด <http://localhost:3000/th>

สั่ง build:

```bash
cd web
npm run build
```

เว็บเป็น static ทั้งหมด — ทั้ง 19 เส้นทาง (ภาษาอังกฤษ 9 + ภาษาไทย 10) ถูก prerender ตอน build

## สร้างเอกสารใหม่

ไฟล์ Word และ Excel ถูกสร้างจากไฟล์ Markdown และไฟล์ข้อมูล Python ใน `build/`:

```bash
python3 -m venv .venv
./.venv/bin/pip install openpyxl python-docx
./.venv/bin/python build/build_xlsx.py        # -> ฐานข้อมูลภาษาอังกฤษ
./.venv/bin/python build/build_xlsx_th.py     # -> ฐานข้อมูลภาษาไทย
./.venv/bin/python build/export_json.py       # -> web/data/*.json
./.venv/bin/python build/export_json_th.py    # -> web/data/th/*.json
```

เนื้อหาต้นทางอยู่ที่ `build/handbook.md` (อังกฤษ), `build/handbook_th.md` (ไทย) และ
`build/ebook_th.md` (ไทย ฉบับเล่าสู่กันฟัง) ส่วนข้อมูลเชิงโครงสร้างอยู่ที่ `build/data_kb.py`,
`build/data_kb_th.py`, `build/data_aux.py` และ `build/data_aux_th.py`

## วิธีวิจัย และข้อจำกัดของมัน

**งานวิจัยทำยังไง** เจาะเธรด geeklist และบล็อกบน BoardGameGeek ที่ว่าด้วยการออกแบบ วิจารณ์
และกระบวนการทำ rulebook; แหล่งปฐมภูมิจาก Stonemaier Games, Resonym, Leder Games และ
Fantasy Flight; style guide อาชีพ (โดยเฉพาะ *Board Game Editing Style Guide* ของ
Michael "Curby" Lee และ *Stonemaier Games Style Guide*); บทสัมภาษณ์บรรณาธิการอาชีพ
รวมถึง Paul Grogan แห่ง Gaming Rules!; และแนวทางด้านการเข้าถึงที่มาจาก WCAG และหลักการ
จัดตัวอักษรสำหรับผู้อ่านที่มีภาวะ dyslexia

**สิ่งที่นี่ไม่ใช่** นี่คืองานวิจัยแบบเจาะจง ไม่ใช่การไล่เก็บทั้งหมด BoardGameGeek มีโพสต์หลักล้าน
และไม่มีช่องทาง export ทั้งชุด เธรดจึงถูกคัดตามความเกี่ยวข้อง ครอบคลุมราวปี 2007–2026
โดยเน้นหนักที่ 2019–2026 ส่วน Reddit ไม่อยู่ในนี้เพราะมันบล็อกการเข้าถึงแบบอัตโนมัติ

**ความเห็นคือความเห็น** มีหลายเกมที่ปรากฏทั้งในรายการที่ควรศึกษาและที่ถูกวิจารณ์ เพราะคนที่มี
ประสบการณ์เห็นต่างกันจริงๆ ไม่มีอะไรในนี้เป็นคำตัดสิน ทุกอย่างมีการอ้างอิง

**ข้อมูลที่เก็บมาไม่ได้ถูกเผยแพร่ซ้ำ** สำเนาโพสต์ในฟอรั่มและบทความของบุคคลที่สามที่เก็บไว้ในเครื่อง
ถูก gitignore ไว้ มีเพียง manifest ของ URL (`research/sources_*.tsv`) เท่านั้นที่อยู่ใน repo
เพื่อให้ทำซ้ำงานวิจัยได้โดยไม่ต้องเผยแพร่ข้อความของคนอื่น

## การอ้างอิง

[Board Game Editing Style Guide](https://cur.by/styleguide) ของ Michael "Curby" Lee
ใช้สัญญาอนุญาต CC BY-NC-SA เนื้อหาที่ต่อยอดจากมัน — โดยเฉพาะแนวทางเรื่อง framing, templating,
คำกริยาช่วย และการเลือกใช้คำ — ถูกอ้างอิงถึงเขาตลอดทั้งคู่มือและฐานข้อมูล

แหล่งอื่นทั้งหมดถูกสรุปและอ้างอิง ไม่ได้คัดลอกมาทั้งชิ้น คำพูดที่ยกมาเป็นข้อความสั้นเพื่อการอ้างอิง
และวิจารณ์ กรุณาตาม URL ในฐานข้อมูลไปอ่านบริบทเต็ม

ถ้าคุณนำเนื้อหานี้ไปใช้ กรุณาลิงก์กลับไปหาต้นทางด้วย พวกเขาคือคนที่ทำส่วนที่ยาก
